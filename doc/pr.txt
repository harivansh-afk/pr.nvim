*pr.txt*  Pull request review for Neovim                              *pr.nvim*

Requires Neovim 0.11+, git, and an authenticated `gh` (GitHub) or `tea`
(Forgejo, Gitea). The forge is whatever `origin` points at. There is no
setup function and nothing to configure.

==============================================================================
COMMANDS                                                         *pr-commands*

                                                                         *:PR*
:PR [list]              Open pull requests of the current repository.
:PR {number}            Review that pull request, open or not.
:PR log [count]         The last [count] commits of HEAD (default 50).
:PR checks              Toggle the CI checks of the pull request or commit
                        under the cursor in the |preview-window|.
:PR threads             Toggle its reviews and comments the same way.
:PR next                Review the next pull request in list order.
:PR prev                Review the previous one.
:PR mark                Mark or unmark the pull request.
:PR marks               Pick a marked pull request with |vim.ui.select()|.
:PR marks {slot}        Review the pull request in that slot.
:PR marks next          Review the next marked pull request.
:PR marks prev          Review the previous one.
:PR draft               Switch between draft and ready.
:PR merge               Merge. |vim.ui.select()| offers the styles the
                        repository allows, each also as "when checks pass".
:PR close               Close without merging, after |confirm()|.
:PR checkout            Check the branch out in your working tree. A local
                        branch with commits the pull request lacks is kept.
:PR browse              Open the thing under the cursor in the browser.
:PR[!] clean            Remove the review worktree. With ! even if modified.

A command acts on the pull request under the cursor, else on the one the
buffer shows, else on the one reviewed last.

==============================================================================
BUFFERS                                                           *pr-buffers*

Every view is an ordinary buffer named by what it shows, loaded by a
|BufReadCmd|. |:edit| reloads it, |CTRL-^| and the |jumplist| move between
them, and the filetype is `pr` (`prlog` for a job log).

    pr://list               open pull requests, stacks indented under
                            their base
    pr://{number}           one pull request: commits, files, inline diffs
    pr://commit/{sha}       one commit, in the same form
    pr://log                commits of HEAD with their CI status
    pr://{number}/checks    CI jobs, worst first, refreshed while any runs
    pr://commit/{sha}/checks
    pr://{number}/threads   reviews, code threads and comments
    pr://job/{id}           one job's log

Checks and threads open in the |preview-window|: |CTRL-W_z| closes it,
|CTRL-W_P| enters it, 'previewheight' bounds it, and it follows the pull
request you move to. A job log folds on its `##[group]` markers (|zj|, |zk|,
|zR|) and conceals timestamps (|'conceallevel'| shows them). Threads fold
one per conversation.

Opening a file checks the pull request out into one detached worktree per
repository under `stdpath("cache")/pr`, so language servers see real files
and your checkout is never touched.

Marks live in `stdpath("state")/pr-marks.json`, per repository.

==============================================================================
MAPPINGS                                                             *pr-maps*

All mappings are buffer-local. There are no global ones; map |:PR| yourself:
>lua
    vim.keymap.set("n", "<C-p>", "<Cmd>PR<CR>")
    vim.keymap.set("n", "<Leader>1", "<Cmd>PR marks 1<CR>")
<
Every pr buffer ~
    g?          this help
    gx          open in the browser
    R  <C-r>    reload, as |:edit|
    -           the pull request list
    q           close the preview window, else go to the alternate buffer

pr://list and pr://{number} ~
    D           draft or ready
    M           merge
    C           check out
    X           close
    A           mark or unmark

pr://list ~
    <CR>        review the pull request
    F           only my pull requests, or everyone's; remembered

pr://{number} and pr://commit/{sha} ~
    <CR>        open the file at the line under the cursor; on a commit,
                show only that commit, or all of them again
    o  gO  O    open the file in a split, a vertical split, a tab
    =           toggle the file's inline diff
    dd          review the diff with diffs.nvim
    dv          the same, side by side
    ]c  [c      next or previous commit, through the whole pull request
    ]f  [f      next or previous file
    ]p  [p      next or previous pull request
    ]m  [m      next or previous marked pull request

pr://log ~
    <CR>        review the commit
    dd  dv      review its diff with diffs.nvim

pr://.../checks ~
    <CR>        open the job log in the previous window
    =           toggle the job's steps, or the tail of its log

pr://{number}/threads ~
    <CR>        jump to the line a thread is about, in the worktree; open
                anything else in the browser
    =           toggle the fold, as |za|

To add or change mappings, use a filetype plugin: >lua
    -- after/ftplugin/pr.lua
    vim.keymap.set("n", "<Tab>", "=", { buffer = true, remap = true })
<
==============================================================================
HIGHLIGHTS                                                     *pr-highlights*

Every group is a default link, so a colorscheme or |:highlight| overrides it.

    PrHeader PrHeading PrNumber PrDraft PrAuthor PrRef PrHash PrStack
    PrMark PrMuted PrSelected PrAdded PrDeleted PrChanged PrHunk
    PrPass PrFail PrRunning PrPending PrSkipped
    PrAnsiRed PrAnsiGreen PrAnsiYellow PrAnsiBlue PrAnsiMagenta PrAnsiCyan
    PrAnsiBold

With diffs.nvim installed, inline diffs are highlighted by it instead.

==============================================================================
LUA                                                                   *pr-lua*

`require("pr")` has one function per command, taking the same arguments:
`list()`, `open(number)`, `log(count)`, `checks()`, `threads()`,
`step(delta, marked)`, `mark()`, `marks(slot)`, `draft()`, `merge()`,
`close()`, `checkout()`, `browse()` and `clean(nil, force)`.
